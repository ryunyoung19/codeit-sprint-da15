# 위클리페이퍼 Week22

### Q1. Git을 처음 배울 때 가장 이해하기 어려웠던 개념은 무엇이었나요? 그 개념을 지금은 어떻게 이해하고 있는지, 초보자에게 설명하듯 풀어서 써보세요.

**터미널에서 현재 위치 파악 + 로컬↔원격 버전 동기화**가 가장 어려웠음

- **폴더 이동**: `pwd`(현재 위치 확인) → `ls`(목록 확인) → `cd`(이동)만 습관화하면 해결
- **버전 동기화**: 로컬과 GitHub은 독립된 저장 공간이고, 오가는 명령어가 정해져 있다고 이해
    - 원격 → 로컬: `git pull` (GitHub에 있는 최신 내용을 내 컴퓨터로 가져오기)
    - 로컬 → 원격: `git add` (변경된 파일 선택) → `git commit` (변경 내용에 이름표 붙이기) → `git push` (GitHub로 올리기)
    - **"먼저 pull로 최신화 → 작업 → push"** 순서만 지키면 충돌이 잘 안 생김


### Q2. 웹 스크래핑과 API 호출은 둘 다 웹에서 데이터를 가져오는 방법입니다. 이 둘의 차이를 설명하고, 어떤 상황에서 각각을 선택하겠나요?

핵심 차이는 **데이터 제공자가 공식적으로 허락한 통로가 있는가**

- **API**: 공식 창구, JSON으로 정제된 응답, 안정적 → 있으면 무조건 우선 선택
- **스크래핑**: 공식 창구 없을 때 HTML을 직접 파싱, 구조 바뀌면 깨지기 쉬움

**실제 경험**: KOBIS 박스오피스는 공식 Open API로 JSON 호출, 씨네21 랭킹은 공식 API가 없어 개발자 도구로 네트워크 요청을 분석해 **숨겨진 JSON 엔드포인트**를 찾아 호출

**선택 기준**: ① API 있으면 API 우선 ② 없으면 네트워크 탭에서 숨겨진 API부터 확인 ③ 정말 없을 때만 BeautifulSoup/Selenium으로 직접 파싱 (이때 robots.txt·약관 확인)
